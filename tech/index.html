Identity on mobile

Will your field apps sign in silently? Find out before you roll out.

Mobile single sign-on is harder than it looks. Native app sign-in is not the same as web sign-in, and a SAML application existing in your identity provider does not mean the mobile app will sign in silently.

Broker-based

On Android, broker-based sign-on depends on the app vendor having compiled a specific authentication library into the app. Apps built without it keep prompting, and no policy setting changes that.

Where authentication happens
Inside the app, through a vendor authentication library
What each app needs
That library, compiled in by the app vendor

Certificate-based

Certificate-based authentication is presented beneath the application layer, so the app vendor does not need to have done anything. The only requirement is SAML support.

Where authentication happens
Beneath the app, from a certificate presented by the tunnel client
What each app needs
SAML support

That one difference decides whether field crews sign in once, or all day.

Certificate-based sign-on requires named-user enrolment, which also changes how devices are staged.
